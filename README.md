# HireLoop

## مسیر شغلی و تمرین

- از «ورود رزومهٔ موجود» متن رزومه را وارد کنید؛ استخراج، پیشنهاد است و فقط پس از مرور و ذخیرهٔ فرم، پروفایل تغییر می‌کند. متن ورودی فعلاً ۶۰ تا ۱۵۰۰۰ نویسه است.
- «جزئیات و تحلیل آگهی» شروط ضروری و ترجیحی را با عبارت منبع نشان می‌دهد. متن کامل تا ۱۲۰۰۰ نویسه قابل وارد کردن است؛ توضیح منبع ممکن است خلاصه باشد. تحلیل خصوصی ذخیره می‌شود، GET و استفادهٔ دوباره از متن ثابت مدل مصرف نمی‌کنند. شرایط نامعلوم به معنی عدم تطابق نیستند.
- «منبع جمله» در رزومه، اطلاعات پشتیبان پیشنهاد را نشان می‌دهد؛ وجود منبع، صحت معنایی جمله را تضمین نمی‌کند. عددهای بی‌پشتوانه کنار گذاشته می‌شوند. ویرایش مستقیم با مقایسهٔ قبل/بعد و بدون AI ذخیره می‌شود. شماره نسخه مانع بازنویسی ویرایش هم‌زمان با ساخت مدل است.
- «تمرین مصاحبه» از دریافت سابقه جدا است: پنج سؤال اصلی و حداکثر یک سؤال تکمیلی برای هر کدام، پاسخ قبل از نمونه، بازخورد و گزارش ذخیره‌شده. شروع و هر پاسخ مدل مصرف می‌کند؛ بازکردن جلسه و گزارش نمی‌کند. امتیاز تمرین احتمال استخدام نیست؛ جواب‌ها وارد پروفایل نمی‌شوند.
- «پیگیری درخواست‌ها» وضعیت، تاریخ و یادداشت را بدون AI نگه می‌دارد. با «ارسال کردم، ثبت همین نسخه» تصویر ثابتی از رزومه ذخیره می‌شود که تغییرهای بعدی آن را عوض نمی‌کنند. بازکردن لینک آگهی ارسال تلقی نمی‌شود.
- دانلود Word یک فایل DOCX واقعی و قابل ویرایش با RTL فارسی یا LTR انگلیسی است. PDF از چاپ مرورگر و «ذخیره به‌صورت PDF» دریافت می‌شود؛ منبع جمله‌ها و گفت‌وگوها در چاپ نمی‌آیند.

جدول‌های جدید با `create_all` در شروع سرور ساخته می‌شوند و ستون یا داده‌ای از جدول‌های قبلی حذف نمی‌شود. هزینه در `/api/usage` ثبت می‌شود. برای تست محلی `PYTHONPATH=backend python -m pytest backend/tests -q` و `npm run build` در frontend اجرا می‌شوند. طرح و قراردادها در `docs/career-workflow-implementation.md` هستند.

همراه تخصصی کاریابی و رزومه‌نویسی برنامه‌نویسان در تمام استک‌ها (Backend, Frontend, Full-Stack, AI/ML, Mobile, DevOps): **مصاحبه هوشمند ← پروفایل استک ← آگهی مناسب با دلیل ← رزومه اختصاصی ← اصلاح و بازخورد**

مصاحبه و جست‌وجوی آگهی‌ها دربرگیرنده تمامی حوزه‌های برنامه‌نویسی و مهندسی نرم‌افزار است (بک‌اند با Python/Go/Node/Java، هوش مصنوعی و یادگیری ماشین، فول‌استک، فرانت‌اند، موبایل و دواپس). سطح کارآموز، تازه‌کار، میانی و ارشد در استخراج و فیلتر آگهی‌ها لحاظ می‌شود. رزومه‌های ذخیره‌شده از تب «رزومه» دوباره باز می‌شوند، حتی اگر نتایج جست‌وجو تغییر کرده باشند. باز کردن نسخهٔ ذخیره‌شده مدل مصرف نمی‌کند.

- **Backend:** FastAPI + Pydantic + SQLAlchemy، JWT، ایجنت‌ها با LangGraph (گراف Refiner)
- **Frontend:** React (Vite) با RTL و فونت Vazirmatn
- **LLM:** هر API سازگار با OpenAI (مثلاً هرموز) — مدل هر ایجنت در `.env`

## تنظیم
۱. فایل `.env` را باز کنید و مقدارهایی که `REPLACE` دارند را پر کنید
   (`LLM_BASE_URL`، `LLM_API_KEY`، نام مدل‌ها، `EMBEDDING_MODEL`، و حتماً `JWT_SECRET`).
۲. جست‌وجوی آگهی از جابینجا، جاب‌ویژن، کوئرا، ایران‌تلنت و کاربوم انجام می‌شود. Tavily در مسیر برنامه استفاده نمی‌شود و کلید جست‌وجو لازم نیست. نام‌های قبلی `HORMOUZ_BASE_URL`، `HORMOUZ_API_KEY` و `HORMOUZ_MODEL` نیز برای تنظیم مدل پشتیبانی می‌شوند؛ فایل `.env` حفظ می‌شود.

## اجرای محلی
```bash
# بک‌اند
cd backend && python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# فرانت‌اند (ترمینال دوم)
cd frontend && npm install && npm run dev      # http://localhost:5173
```

## دیپلوی روی سرور

نسخهٔ آنلاین: https://78.157.54.151/

استقرار روی سرور مشترک منتورا با Nginx، systemd و دیپلوی خودکار GitHub Actions انجام می‌شود. مسیر فایل‌ها، پشتیبان‌گیری و فرمان‌های نگهداری در [راهنمای استقرار](deploy/README.md) هستند.

برای سرور مستقل با Docker:
```bash
docker compose up -d --build     # سایت روی پورت ۸۰
```

## تست
```bash
cd backend && pytest -q          # کل جریان با LLM جعلی؛ بدون API key
```

## معماری کوتاه
| ایجنت | فایل | نقش |
|---|---|---|
| Interviewer | `agents.py` | جمع‌آوری سابقه؛ نقش و دو مهارت واقعی برای شروع جست‌وجو کافی است |
| Matcher | `services.py` | فیلتر سخت ← embedding ← امتیاز و توضیح LLM |
| Resume Writer | `services.py` | رزومه فقط از واقعیت‌های پروفایل (+ محافظ ضدجعل برای مهارت‌ها) |
| Refiner | `agents.py` | گراف LangGraph: انتخاب اقدام (تغییر ترجیح / حذف آگهی / اصلاح رزومه / پاسخ) |

دریافت آگهی در `backend/app/jobs.py` است: HTML برای جابینجا، کوئرا و کاربوم؛ درخواست JSON رابط سایت برای جاب‌ویژن و ایران‌تلنت. هر منبع حداکثر دو عبارت و صفحهٔ اول را جست‌وجو می‌کند، همهٔ کارت‌های معتبر همان جست‌وجو را تا سقف مهلت ۳۵ ثانیه بررسی می‌کند. متن اصلی، شناسه، بنر انقضا و تاریخ اعتبار بررسی می‌شوند؛ صفحهٔ بدون متن JobPosting وارد تطبیق نمی‌شود. پاسخ موفق پنج دقیقه در حافظه کش می‌شود. این مسیرها API عمومی تضمین‌شده نیستند.

شهر، دورکاری و سطح کارآموز با کمبود نتیجه خودکار کنار گذاشته نمی‌شوند. آگهی‌های نمونهٔ قدیمی در دیتابیس حفظ می‌شوند ولی وارد نتایج نمی‌شوند. شکست همهٔ منابع نتایج قبلی را حفظ می‌کند و با هشدار نمایش می‌دهد. وضعیت هر سایت و لینک آگهی اصلی در صفحهٔ نتایج دیده می‌شود. دریافت و بررسی آگهی مدل مصرف نمی‌کند؛ همهٔ آگهی‌های عبورکرده از فیلتر سخت ارزیابی می‌شوند و در فرانت هر صفحه ۱۲ آگهی نمایش داده می‌شود.

جست‌وجوی عمومی کاربوم و یک آگهی تازهٔ دارای JobPosting بررسی شده‌اند؛ بعضی آگهی‌های آن این داده را ندارند و فعلاً کنار گذاشته می‌شوند. مجوز تجاری استفاده از مسیرهای داخلی سایت‌ها هنوز تأیید نشده؛ شواهد و شرایط منابع در `docs/search-benchmark-api-research.md` و `docs/karboom-source-notes.md` ثبت شده‌اند.

مصرف توکن هر فراخوانی در جدول `usage` ذخیره می‌شود؛ `GET /api/usage` جمع‌ها را می‌دهد.

## مرور پروفایل و رزومهٔ متناسب با آگهی
«مرور و ویرایش اطلاعات» در مصاحبه و صفحهٔ رزومه، تغییر یا حذف مهارت‌ها، پروژه‌ها، سابقه، تحصیلات و راه‌های ارتباط را بدون فراخوانی مدل ذخیره می‌کند. حداقل اطلاعات جست‌وجو با کامل بودن اطلاعات رزومه فرق دارد؛ نام و جزئیات پروژه مانع شروع جست‌وجو نمی‌شوند.

قبل از ساخت رزومه، حداکثر سه سؤال از مهارت‌های ذکرنشدهٔ آگهی و جزئیات ناقص پروژه یا سابقه نشان داده می‌شود. انتخاب سؤال مدل مصرف نمی‌کند؛ پاسخ «تجربه دارم» به توضیح نیاز دارد و فقط برای همان آگهی استفاده می‌شود. پاسخ‌ها در JSON پروفایل، جدا از مهارت‌های عمومی کاربر ذخیره می‌شوند؛ تغییر پروفایل یا آگهی نیاز به تأیید مجدد دارد. مهارت‌های استخراج‌نشده از منبع فعلاً سؤال اختصاصی ندارند و تشخیص کامل بودن شرح پروژه با طول متن انجام می‌شود.

باز کردن رزومه یا تغییر زبان، خودکار رزومه تولید نمی‌کند؛ کاربر دکمهٔ ساخت را می‌زند. نسخهٔ موجود تا موفق شدن ساخت جدید حفظ می‌شود. کنار رزومه مهارت‌های مرتبط و نیازهای ذکر یا تأییدنشده نشان داده می‌شوند؛ این توضیح در PDF نمی‌آید. کنترل مهارت‌ها قطعی است؛ صحت شرح دستاوردها علاوه بر دستور مدل به مرور کاربر نیاز دارد.
